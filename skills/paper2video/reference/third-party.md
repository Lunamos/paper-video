# Starting from an arXiv link or a title (someone else's paper)

Most videos start with nothing but `arXiv:XXXX.XXXXX` or a paper title, no repo access and no GPU. This file covers finding the material, getting real numbers out of it, and staying faithful to authors you are not.

## 1. Collect everything public (into `data/`, git-ignored)
1. **Resolve the paper**: from a title, search arXiv (`http://export.arxiv.org/api/query?search_query=ti:"..."`) and confirm authors/year; note the latest version number and use it as the source of truth (record `vN` in `CLAUDE.md`).
2. **PDF and LaTeX source**: `https://arxiv.org/pdf/<id>` and the source tarball `https://arxiv.org/e-print/<id>` (gzip'd tar, sometimes a single gzip'd .tex). Extract to `data/paper/src/`. The source gives exact table values, macros/notation for KaTeX, captions, and the figure files.
3. **Code, project page, data**: links in the abstract/paper/README of the source; the arXiv page's "Code, Data, Media" section; Papers with Code; GitHub search by title; Hugging Face (models, datasets, Spaces) by title or author; the authors' homepages. Note licences.
- **Web-article papers** (Distill-style pages such as transformer-circuits.pub, no LaTeX): convert the page to clean text with a small HTMLParser script that drops script/style/svg before reading. Interactive figures usually load clean JSON/CSV from a `data/…` folder — find the file names in the page's JS bundle (e.g. `getFile(datapath + '…')`) and fetch those: exact numbers, no digitising. Released data inside a large zip: read only the members you need with HTTP range requests (the zip's central directory is at the end) instead of downloading it all.
4. **Talks/blogs/threads** by the authors can show which result they consider the headline — useful for emphasis, never as a number source.

## 2. Getting numbers, in order of preference
1. **Tables in the LaTeX source** — parse the `tabular` directly.
2. **Released results**: JSON/CSV/logs in the repo, released checkpoints' eval files, Hugging Face dataset cards.
3. **Figure data embedded in the source**: pgfplots/TikZ coordinates or `\addplot table` files. Figure PDFs from matplotlib are usually **vector**: every marker, bar and line is a path with exact coordinates. `scripts/figdata.py dump fig.pdf` lists the drawings (type, colours, points) and the text spans (tick labels, value labels) with positions; map two labelled ticks per axis to their tick marks (not label centres) and convert. Value labels printed on the plot are the best numbers of all — snap to them. For a broken axis or several panels, use drawing order to tell which axes a path belongs to (matplotlib draws each axes' content together).
4. **Colour-coded cells** (token heatmaps, confusion matrices, attention maps): `figdata.py heatmap` inverts the fill colours through the colormap's LUT (exact when the worst LUT distance is ~1e-6) and reads the text inside each cell per character.
5. **Plotting scripts in the repo** that re-create a figure from shipped data — run them on CPU and export the arrays. Notebooks often carry printed outputs (means, baselines) that make good cross-checks for the text; the paper still wins when they differ (released code is often refactored and drifts a little).
6. **Digitising raster figures** (last resort; many "vector" PDFs only wrap a PNG — `figdata.py images` extracts it): `figdata.py markers` calibrates from the tick marks, finds marker centres by colour on the evaluation grid, handles markers hidden under a series drawn later, and writes an overlay image — look at it. Bars and histograms: find bar tops by colour per column; calibrate from grid lines where tick marks are hidden. Record the expected error (≈ ±1 px in data units). Mark such charts on screen as "digitised from Fig. N", replace points that carry printed values (stars, labels) with the printed numbers — and mask those glyphs while digitising (`--avoid x,y`): a star's arms are wider than a marker and get taken for the points next to it — and quote only numbers that appear in the text or tables.
7. **Small reproductions for illustration** — only when cheap and clearly labelled: e.g. one forward pass of a small public model over the paper's own example to show next-token probabilities. Say on screen what was run ("illustration · Qwen3-0.6B, run for this video"), keep it out of any "the paper shows" sentence, and never compare it numerically against the paper's results. No training, no large downloads without asking (ask above ~5 GB). CPU is enough for a sub-1B model on a few thousand tokens; if the user offers a GPU machine instead, work in a temporary directory they name, reuse an existing environment rather than installing, point caches (`HF_HOME`) into that directory, keep the job short, copy back only the small JSON result, and delete exactly that directory afterwards (list it before deleting). The cheapest useful run is usually the authors' own extraction script on one layer of a small model: seconds of GPU, a small `.npy` copied back, the analysis done locally with numpy, labelled "run for this video".

**Validate every extraction against numbers the paper prints**: totals ("over 10^6 tokens"), percentiles ("the top 20% exceed 0.672"), shares, maxima equal to the stars or table values, curves that end where the text says they do. Two independent checks passing is what lets the data report say "no discrepancy found". Then verify the digitised data itself, before the video is final:
- **which panel is which**: match each extracted raster panel to its sub-caption by its position in the figure PDF (`figdata.py images` prints the placement);
- **calibration twice**: tick marks and tick-label centres must agree within a pixel or two (an off-by-one tick shows up as a whole tick spacing);
- **draw the data back onto the original** (every point as a dot on the paper's own panel) and look: a point off its marker is wrong, whatever the code says;
- **twin panels**: papers often plot the same runs twice (a main figure and an ablation); digitise both and compare point by point — this catches markers hidden under another series or under a semi-transparent reference line (which splits a marker and biases the marker finder); take the unhidden copy;
- **precision**: keep values to ~1/1000 of the axis range (rounding entropy on a 0.10–0.35 axis to 0.01 moves points by 2 %);
- show the user a paper-vs-video comparison of every chart if they ask whether the data are right — it answers the question faster than any table.

Record every source in `notes/data_report.md` (which file/table/figure, which method, expected error).

## 3. Faithfulness for someone else's work
- The video explains the authors' work. Say "the authors" / "this paper" / "作者" / "这篇论文"; never "we" or "our method". Name the authors and institutions on screen near the start (title card), and link the paper in the descriptions.
- No new claims, no opinions dressed as findings, no "SOTA" unless the paper says so for that setting. Keep their terminology and notation. Keep each result inside its scope (the setting it was measured in); if a result is contested elsewhere, either leave it out or say so neutrally only if the user asks.
- Little creative re-framing, but **selection is required**: keep the paper's own logic for the parts you show (motivation → observation → method → results), and choose those parts — the headline finding and its strongest evidence. A 4-minute film cannot cover a paper section by section; leaving out a derivation, a side experiment or a list of implications is not unfaithful, distorting a result is. Mention what was left out in the description ("also in the paper: …"). Analogies are fine to explain a concept, not to strengthen a result.
- Impact (well-known older papers): what came after is part of the story — follow-up papers (by name and year), methods or fields it started, how it is used today. Every such fact gets a source in `notes/claims.md` like any number; present follow-ups that disagree neutrally; don't credit the paper with more than the sources say.
- Limitations: no scene for them unless the paper treats them as a central part of its contribution; then the one to three that matter, ≤ 20 s. Scope is carried by stating the setting of each result.
- Restore the authors' intent: present each experiment as the question they asked and the setup they chose (their own framing — section titles, takeaway boxes, figure captions), including what they tried that did not work when the paper reports it. That is usually where the fun is, and it is faithful by construction.
- Redraw figures from data rather than pasting the paper's figure images; if an original figure is shown (e.g. a qualitative example), show it small, credited ("Figure 3 of <paper>"), and only briefly. Check the paper's licence (arXiv licence on the abs page); when in doubt, redraw.
- Thumbnails/titles describe the finding, not the authors' reputation; don't imply endorsement by the authors or their institutions. Add a line in descriptions: "Unofficial explainer of <title> by <authors>." (and the Chinese equivalent 「非官方解读」).
